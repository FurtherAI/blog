Context Parallelism in ART

From one attention query to a distributed tree.

September 2026 · About an hour, plus optional derivations

A GPU does not need every token to compute its part of a sequence. It needs the right information about the other tokens. Finding that information, moving it at the right time, and leaving the expensive arithmetic in efficient kernels is the central problem of context parallelism.

I started this project with three hypotheses: context parallelism could move less data than tensor parallelism, hide that communication behind the computation it serves, and lower activation memory per GPU. The especially interesting opportunity was reinforcement learning. A training batch often contains several trajectories with the same long prompt. Prefix-tree packing lets us compute that prompt once. A larger packed row can then hold more new trajectories, rather than more copies of old context.

The practical results were stronger than a way to make longer sequences fit. On the workloads we measured, context parallelism became a useful throughput axis. Dense attention stayed nearly constant in time as we increased both GPUs and packed tokens. A GLM-5.2 training experiment retained about 95% weak-scaling efficiency when growing from eight to sixteen H200s across two nodes. But these results do not come from one universal distributed kernel. Attention, learned sparse attention, Gated DeltaNet, and Mamba-2 offer different ways to separate their work.

This article develops those ways from the beginning. We will follow a query, its normalization, and its gradients before introducing a planner. Then we will change the layer and ask what information has to cross a GPU boundary now. The expandable sections carry the detailed derivations; the main text explains why the derivations matter for execution.

01 / The workload

What does a longer packed row buy us?

It buys room for more unique work. With a shared prompt, that can mean substantially more completed trajectories per pass through the model.

A trajectory here is one prompt followed by one sampled completion. Several trajectories can share a prompt, or share a longer conversation before branching. The model must produce the same outputs as if each trajectory had run separately. It must not let a completion read another completion. But computation on an identical, non-trainable prefix can be shared.

It helps to distinguish two lengths. Logical length is the context seen by a trajectory along its root-to-leaf path. Physical length is the number of stored token positions in the packed row. A tree with a 24K prompt and five 8K completions has 64K physical tokens, while every trajectory has a 32K logical context. Throughout the capacity examples, K means 1,024. A longer physical row is not necessarily a longer context for any individual query.

one prompt of length P, completions of lengths C_1 ... C_m

flattened storage = m * P + sum(C_i)
tree storage      =     P + sum(C_i)

The saving is not limited to storage. Tokenwise projections and MLPs process the prompt once. Dense causal attention computes its prompt-to-prompt triangle once. The completion-to-prompt rectangles still exist: every completion needs to read the prompt. Sharing removes duplicated computation, not legitimate dependencies.

Context parallelism (CP) partitions tokens among a group of GPUs. A rank is one participating process, normally one GPU. CP4 means four ranks collaborate on this packed row. The model parameters need not be partitioned by CP itself: each rank can apply the same linear layer to a different set of tokens. Other parallelisms can partition parameters at the same time.

This differs from tensor parallelism (TP), which splits a layer's channels or matrix dimensions and combines partial results. Pipeline parallelism (PP) splits layers across stages. Expert parallelism (EP) splits the experts of a mixture-of-experts model and routes token activations to them. These are composable axes, not four competing names for the same operation. In many of our large-model runs, CP handles sequence-dependent work and EP provides the necessary expert-weight sharding.

The scaling question must match the workload

In strong scaling, we keep a problem fixed and ask more GPUs to finish it faster. In weak scaling, we give N times as much work to N times as many GPUs and ask them to finish in the same time, with similar memory per GPU. The second question is especially natural for training a larger collection of trajectories.

There is a crucial qualification for attention. Making one causal sequence N times longer creates roughly N squared times as many query-key pairs. That is not constant work per GPU. Our ordinary weak-scaling workloads instead add independently sized families of prompts and completions until the larger packed row fills. Family shapes have the same distribution, so token count and visible attention-pair count grow roughly together. A fixed global long-chain experiment is a different, explicitly labeled strong-scaling test.

Prefix reuse and CP therefore help in two distinct ways. Reuse reduces the work represented by a collection of trajectories. CP distributes the remaining work and grows the capacity of the row. The capacity figure explains the first opportunity; the runtime measurements later test the second. We should not infer the runtime of 29 trajectories merely from the fact that they fit.

Derivation: capacity and attention work for one family

For equal completion length C and row capacity S, flattened trajectories occupy P+C tokens each. A tree pays P once. Ignoring all packing constraints except capacity:

m_flat = floor(S / (P + C))
m_tree = floor((S - P) / C), for S >= P

visible pairs in the tree:
A_tree = P(P+1)/2 + sum_i [C_i P + C_i(C_i+1)/2]

A_flat - A_tree = (m-1) P(P+1)/2

The rectangle C_i P remains in both executions. So does each completion's own triangle. With a deeper tree, add one causal triangle for each physical segment and one rectangle between that segment and each of its ancestors. Unrelated branches contribute no pair. This is the work-counting rule the planner must respect.

Tree sharing also requires matching all semantics along a shared path: token identities, position IDs, masks, and the treatment of stochastic operations. ART keeps trainable tokens in leaves so independent loss contributions are not silently collapsed into one shared target. Gradients from multiple descendants still add at their common prefix. The prefix-tree article covers the packing contract; CP must preserve it.

02 / Start on one GPU

What information defines one attention output?

A weighted sum of values and its normalization. This small interface is what lets us split attention without approximating it.

For one attention head, a linear projection produces a query q for the token whose output we want, a key k_j for every token it may read, and a value v_j to read from that token. A dot product measures query-key compatibility. Softmax turns the scores into positive weights summing to one. A mask excludes keys that this query must not see.

s_j = dot(q, k_j) / sqrt(d) + any allowed score bias
p_j = exp(s_j) / sum_visible_keys exp(s_k)
o   = sum_visible_keys p_j * v_j

Here d is the query/key head dimension; o has the value dimension. We will omit the head index when the same reasoning applies independently to each head. In grouped-query attention, several query heads share one KV head. This reduces the amount of KV data stored and moved, even though each query head still computes its own scores.

For a causal sequence, query i can read positions up through i. For a tree, it can read earlier tokens in its own segment and all tokens in its ancestors. Notice what is absent from the formula: no term requires visible keys to be adjacent in memory, on the same GPU, or processed in a particular tile order. Those are implementation choices. Only membership in the visible set and correct normalization matter.

Efficient attention already avoids the giant matrix

The naive implementation forms a score matrix with one row per query and one column per key. At long context this intermediate is enormous. FlashAttention instead visits tiles of keys, keeps small running statistics, and never writes the complete probability matrix to GPU memory. Its major contribution is reducing traffic to high-bandwidth memory (HBM), the GPU's large off-chip memory, while retaining exact attention in real arithmetic. FlashAttention paper.

ART wants to retain that efficient inner computation. The local attention kernel should still perform its dot products, softmax, and value accumulation using its tuned GPU schedule. Distributed execution should provide the kernel with an appropriate query block, a KV block, and a mask, then combine its answers. Replacing a mature attention kernel with a Python-level distributed formula would lose the benefit we are trying to preserve.

The extra result we need from each kernel call is log-sum-exp, abbreviated LSE. For this query and this subset of keys, LSE is the logarithm of the softmax denominator. Keeping it in log space avoids overflowing exp(s) when scores are large.

L_A = log(sum_{j in A} exp(s_j))
o_A = sum_{j in A} exp(s_j - L_A) * v_j

The pair (o_A, L_A) summarizes everything subset A contributes to this query's output. It is not a reusable compression of those keys for every possible query: change q and both quantities change. It is a sufficient summary for merging this query's already-computed attention. That distinction will matter when we compare attention with recurrent state later.

In ART's dense path, PyTorch FlexAttention supplies the local operator and mask interface, with the qualified Flash backend for the H200 measurements in this article. ART supplies the work decomposition, movement of ranges, and merge around it. A kernel launch is not synonymous with a complete layer: one distributed layer can invoke several local attention stages, as well as small layout and merge kernels.

03 / Partition the same computation

Keep the query; bring it the keys it needs

A query's owner computes its complete output, using local KV immediately and remote KV in scheduled stages.

Let us use a tiny tree for the rest of the attention discussion. Its root has four tokens, physical positions 0 through 3. Completion A occupies 4 through 6. Completion B occupies 7 and 8. These are addresses in the packed row, not one causal sequence of length nine. Query 6 can see 0 through 6. Query 8 can see 0 through 3, then 7 and 8; it cannot see A.

For an illustrative two-rank assignment, rank 0 owns tokens {0,1,4,5,6}; rank 1 owns {2,3,7,8}. This assignment is not claimed to be optimal. It makes an important point visible: each rank's tokens can consist of several disjoint ranges. The owner stores the residual activations for those tokens and performs their token-local work. Initially it also holds their projected Q, K, and V.

Rank 0 can start query 6's attention against its local visible keys {0,1,4,5,6}. In parallel it requests the needed remote KV range {2,3}. Once that range is ready, another kernel computes query 6 against those keys. A stage is one such local attention computation over a planned query/KV subset. A wave groups remote ranges into a scheduled exchange and the computation that consumes them.

We do not need to broadcast Q to every KV owner in this design. Q remains at its owner, and the final O stays there too. That keeps the output projection, residual addition, normalization, and subsequent tokenwise work local to the same owner. Remote KVs are temporary inputs, not a change of ownership. Multiple local queries can reuse a fetched KV range; it should not be sent again for every query.

Two softmax outputs cannot simply be averaged

Each stage normalizes over a different set of keys. If the local stage accounts for 30% of the total exponential score mass and the remote stage accounts for 70%, their outputs must receive those weights. Counting keys does not give the weights; two very high-scoring keys may dominate two hundred low-scoring keys.

L = logaddexp(L_A, L_B)
o = exp(L_A - L) * o_A + exp(L_B - L) * o_B

The expression logaddexp(a,b) means log(exp(a)+exp(b)), evaluated stably. The two multipliers sum to one. The result is precisely the output that a single attention call over A union B would produce, up to floating-point evaluation order. It is also composable: merge two stages, then merge the result with a third.

This is why CP can build on a fast attention kernel. Its inner dot products and softmax do not become distributed operations. The distributed layer asks for the local O and LSE, then uses a comparatively small merge over query rows. ART fuses these gathers and merges where possible, rather than leaving chains of indexing, casts, and temporary tensors between large kernels.

Communication has a deadline, not just a byte count

A CUDA stream is an ordered queue of GPU operations. Work on different streams can overlap when the hardware and data dependencies permit it. ART uses that separation to begin a remote KV fetch while the compute stream runs local attention. It then waits for the fetch only where a remote stage actually needs the data. Later fetches can be issued while earlier remote stages compute.

Suppose local compute lasts 5 ms and a KV fetch lasts 3 ms. The fetch consumes network resources, but it need not add 3 ms to the layer's wall time. If the same fetch takes 7 ms, the compute stream waits about 2 ms after local compute. We call that delay exposed communication. More generally it is communication on the layer's critical path, the chain of dependencies that determines when the layer can finish.

The schedule cannot hide everything just by assigning more streams. Packing a send buffer must finish before its transfer reads it; attention must wait for its receive buffer; the buffer must remain alive while either stream uses it. GPU memory bandwidth and compute resources may also be shared between communication, packing, and attention. These constraints are part of the execution we measure, not overhead assumed away by an asynchronous API.

Derivation: stable attention merging, empty stages, and associativity

For disjoint visible key sets A and B, define unnormalized vectors N_A = sum exp(s_j)v_j and scalar masses Z_A = sum exp(s_j), with corresponding quantities for B. Then o_A=N_A/Z_A. Direct substitution gives:

o = (N_A + N_B) / (Z_A + Z_B)
  = [Z_A / (Z_A + Z_B)] o_A
    + [Z_B / (Z_A + Z_B)] o_B.

L_A=log Z_A and L_B=log Z_B recover the weights without representing large Z values. Let m=max(L_A,L_B). Compute:

a = exp(L_A - m)
b = exp(L_B - m)
L = m + log(a + b)
o = (a * o_A + b * o_B) / (a + b)

Associativity follows because the underlying representation is addition of (N,Z). It is exact in real arithmetic, not a promise of bitwise identity across different FP32 or BF16 reduction orders. Accumulating merge statistics at higher precision reduces the error introduced outside the local kernel.

A stage with no visible key has Z=0. Its neutral representation is output zero and LSE negative infinity, with explicit handling of the all-empty case to avoid negative-infinity minus negative-infinity. Every real query must retain the visibility required by the model. An all-masked padding query must not accidentally acquire a nonzero output or gradient.

Disjointness is substantive. If a fetched key appears twice in the sets being merged, it contributes twice to both numerator and denominator and changes the answer. Range deduplication and stage masks are therefore correctness mechanisms, not only memory optimizations. The same rules hold per query and per head when different rows see different stage subsets.

04 / Close the ownership loop

Where do the gradients go?

dQ stays with the query owner. Contributions to remote dK and dV must return to the token owner and be added there.

In a normal attention backward pass, each query contributes to its own q gradient and to the k and v gradients of all keys it read. A shared root may be read by hundreds of completion queries. Those contributions add. CP changes where they are produced, not how many there are or how they should be summed.

Return to query 6 on rank 0. Its local stage produces gradient contributions for local keys {0,1,4,5,6}. Its remote stage produces contributions for keys {2,3}. Those two remote tokens are owned by rank 1, which may also produce dKV for them from its own queries. Rank 0 must send its contributions back, and rank 1 must add them to the others before running the relevant projection backward.

The transpose of a gather that replicates values is an accumulation, not a plain copy. If three ranks fetch one root KV, backward has three contributions to that KV. If a rank has no useful tokens in a particular stage, it still has to obey the collective schedule when other ranks need its participation. A zero-sized tensor does not grant permission to skip an ordered collective.

There is a second gradient sum outside the attention operator. If CP ranks use replicated projection or MLP weights on different tokens, each rank computes only its token subset's contribution to those parameter gradients. The training system must reduce them with the model's intended loss normalization. Returning dKV to its token owner does not replace parameter-gradient reduction. EP and TP change which parameters are shared and which groups perform those sums; a correct topology must account for both kinds of ownership.

Use the global softmax derivative

Backward must also respect the normalization we just merged. For a query with incoming output gradient g, define D=dot(g,o), where o is the complete attention output. The derivative of a score is p_j times (dot(g,v_j)-D). The D term couples all visible keys, including keys handled by other stages.

There are two equivalent interfaces for an efficient staged backward. A kernel can use the saved global O and LSE directly. Or the merge backward can produce the appropriate adjoints for each local O and LSE. What is not correct is to run every stage's ordinary softmax backward with the original g and pretend the local denominators were global. ART's stage and merge machinery supplies this missing information around the local backward kernels.

After a remote stage's backward produces dKV, its return can overlap backward compute for another stage. Near the end, however, all outstanding contributions must be complete before the owner consumes its final gradients. This gives backward both a useful overlap opportunity and a possible communication tail.

This explains why a profiler's summed kernel times are not the layer time. Concurrent communication and compute overlap. CPU launch ranges can contain queueing or compilation rather than GPU execution. To reconcile a profile, we need a wall-clock span, stream dependencies, and the union of intervals on the critical path. Adding all visible bars can count the same millisecond twice.

Derivation: the gradient of the merge and the attention stages

Let the full output be o=sum_r w_r o_r, where w_r=exp(L_r-L) and L=logsumexp_r L_r. With scalar loss J and g=dJ/do, differentiation gives:

dJ / do_r = w_r * g
dJ / dL_r = w_r * dot(g, o_r - o)

Within stage r, p_local_j=exp(s_j-L_r) and dp_local follows the ordinary softmax derivative. The local-output adjoint contributes w_r p_local_j dot(g,v_j-o_r) to dJ/ds_j. LSE has derivative dL_r/ds_j=p_local_j, so its adjoint contributes w_r p_local_j dot(g,o_r-o). Adding cancels o_r:

dJ/ds_j = p_global_j * dot(g, v_j - o)
p_global_j = w_r * p_local_j

dV_j += p_global_j * g
dQ   += (dJ/ds_j) * K_j / sqrt(d)
dK_j += (dJ/ds_j) * Q   / sqrt(d)

These equations are for one query and head. Sum across queries and across query heads that share a KV head. Score biases or learned sinks have their own derivatives. A distributed implementation must accumulate all consumers' contributions once, at the canonical parameter/token ownership used by the rest of the model.

If backward recomputes probabilities instead of storing them, it uses the same scores and the saved global normalization. This trades repeated arithmetic for much less activation memory. CP does not require retaining a global attention probability matrix; nor should a convenience wrapper accidentally materialize one.

The useful invariant for a communication audit is simple: every forward copy from owner a to consumer b has one backward contribution from b to a. Many forward copies imply a sum. A permutation has an inverse permutation; a replicated gather has a scatter-add. Check these distinctions before attributing a large gradient discrepancy to floating-point noise.

05 / Turn algebra into a schedule

Equal tokens are not equal work

The planner chooses ownership and communication waves to reduce the slowest rank's predicted completion time, not simply to make token counts match.

On an ordinary causal sequence, early queries read few keys and late queries read many. Split the sequence into equal contiguous intervals and the last rank gets much more attention work. A ring can circulate KV shards correctly, yet still leave early-query ranks underused. The communication algorithm and the load-balancing problem are different problems.

In ring attention, each rank starts with its local Q/K/V, computes against a KV shard, then passes that shard to the next rank while receiving another. Repeating the rotation visits the required remote KVs. The output/LSE merge keeps a running answer without retaining every shard at once. It is a useful distributed analogue of tiled attention. The limitation relevant here is not the merge math; it is committing to a regular circulation and ownership pattern when the useful work is irregular.

A familiar improvement is a zigzag or folded assignment. Give each rank one early piece and one late piece. Their causal workloads partly compensate: a cheap early piece accompanies an expensive late piece. For one regular causal triangle, this is a good geometrical shortcut. It can still reuse the same local attention kernel and the same merge algebra.

For eight causal tokens, query workloads are 1,2,3,4,5,6,7,8 visible keys. A contiguous two-rank split gives 10 versus 26 pairs. Split into four two-token blocks instead: their work is 3,7,11,15. Assigning the first and last to one rank and the middle two to the other gives 18 pairs each. That is the intuition behind the fold; it is not a change to which keys a query may read.

Now replace the triangle with our tree. Late physical positions are not necessarily expensive. They may belong to short independent branches. A shared root is read by many branches, so placing it affects KV traffic as well as its own query work. With sliding windows, a late query may read only a short path suffix. No fixed fold of the packed row captures all these cases.

The idea we took from MagiAttention

MagiAttention was the central inspiration: decompose attention into distributable work and let a planner decide its placement. The essential step is to stop treating a rank's contiguous sequence interval as a law of attention. A plan may assign different collections of query work to different ranks, then schedule the required data movement.

ART did not import MagiAttention's entire runtime or its attention kernel. Nor did we impose a restriction that all supported masks must be only full rectangles or causal triangles. Those shapes often occur in trees and are useful for explaining them, but the executor's masking interface preserves more general visibility. The inheritance is the decomposition-and-planning approach; the local dense arithmetic remains in the FlexAttention stack.

Three objects the planner must keep separate

First is visibility: which query-key pairs are valid. Second is ownership: where the token activations live. Third is the execution schedule: which query/KV subsets run in which stages and when their data arrives. Visibility is fixed by model and tree semantics. Ownership and scheduling may change to improve performance without changing visibility.

Searching all assignments of individual tokens is hopeless. ART groups nearby physical tokens into contiguous chunks for planning. A rank may own any collection of these chunks; its whole assignment need not be contiguous. Contiguity limits the search space and makes movement representable as a compact set of ranges. It is not a mathematical constraint that neighboring tokens must execute together.

The planner counts visible pairs between query chunk i and key chunk j. A matrix W[i,j] records these counts. Summing a query chunk's row estimates its arithmetic. The nonzero columns identify the KV it needs. After assigning owners, those same columns determine local work, remote dependencies, and opportunities to share one fetch across several queries.

Token-local work must not disappear from the objective either. A root's early queries may be cheap in attention but still run projections and an MLP. Giving one rank most tokens to equalize only attention pairs can make that rank the bottleneck in the surrounding model. Geometry, model-derived work profiles, and memory constraints complement the attention-time prediction.

Consider a root chunk used by ten query chunks on one rank. Its arithmetic contributes to ten query-key interactions, but its KV need only be fetched once for a stage containing those queries. A model that charges one transfer per interaction overestimates traffic. A model that balances only pair counts misses this reuse and may create an unnecessarily fragmented plan.

Predict milliseconds on the actual execution shape

Visible pair count is a useful starting point, not a complete runtime model. Tiny attention calls underfill the GPU. More ranges require gathering and assembly. Each stage adds launch and merge work. A remote transfer costs latency as well as bytes divided by bandwidth. Forward and backward have different throughput and different overlap opportunities.

The generic dense planner uses calibrated coefficients for these effects and simulates the stage schedule. Local and remote attention have distinct forward/backward pair-time coefficients. A measured underfill term accounts for small remote stages. Range counts approximate layout overhead. Communication coefficients must reflect the hardware; explicit rank-to-node link profiles in later planner work further distinguish cross-node traffic from local traffic. The measured snapshot is not a claim that one bandwidth coefficient predicts every placement.

stage time ~= launch cost
            + visible pairs / achieved pair throughput
            + merge work + range handling + underfill

transfer time ~= latency + bytes / achieved bandwidth

start next compute = max(compute available, required KV ready)
finish backward    = max(compute finished, all dKV returned)

These are empirical predictions, not proofs or peak-FLOP estimates. A coefficient should explain observed runtime across execution shapes; it should not be chosen merely to make a named benchmark select a desired plan. The simulator is also an approximation: contention and CPU scheduling can make actual overlap worse. Comparing predicted and measured times on alternative plans is the test of whether its decisions deserve trust.

The bounded search starts from reasonable chunk assignments, tries a limited set of wave counts, and evaluates candidate ownership moves around costly ranks. It stops when it cannot find a worthwhile improvement or reaches its search budget. This avoids exponential enumeration. More waves can improve overlap and limit temporary memory, but they also create more small calls. Fewer waves reduce launches, but can delay useful compute or enlarge working buffers.

Architecture-specific planners need architecture-specific work. GLM's profile includes indexer tile pairs, sparse-attention and projection work, bytes, memory, peers, and fragmentation; its resource-based comparisons are not identical to the generic dense scalar-time model. GDN has a separate runtime model for local versus chained recurrence. Calling all of these simply “balanced tokens” would hide the most important decision they make.

The plan is per input, not per layer

A changing packed tree requires a new visibility layout and potentially a new ownership plan. But dozens of compatible model layers can use that plan. CPU lookahead prepares future inputs while the GPU executes the current one. GPU block metadata is materialized for a prepared plan and reused where the attention geometry matches. Tensor values, such as actual Q and K, are still computed afresh in every layer.

Block metadata tells the local attention kernel which query/key tiles contain valid work, which are entirely visible, and which require an elementwise mask check. It is not a stored dense probability matrix. Compact construction is important at long context: materializing a temporary token-by-token Boolean mask can consume more memory than the attention operation itself. ART's preparation constructs the kernel's required representation without changing the visibility the kernel receives.

That separation is why a 40 ms planning time need not add 40 ms to every layer. It is also why we must report it. If lookahead cannot keep up, the model waits. If a new input repeatedly triggers compilation, the nominally fast layer is not fast in training. Caching an exactly repeated tree is useful in a fixed-input benchmark, but cannot establish performance on varying completions.

Implementation: a small critical-path simulator

This pseudocode illustrates the dense planner's timing logic, not its full search or data structures. Fetch j+1 is started when stage j can run; we do not assume infinite simultaneous fetches. All times are elapsed milliseconds in the model.

compute_done = local_attention_ms
fetch_ready = first_fetch_ms

for stage in remote_stages:
    start = max(compute_done, fetch_ready)
    fetch_ready = start + stage.next_fetch_ms
    compute_done = start + stage.attention_and_merge_ms

forward_done = compute_done

compute_done = 0
returns_done = []
for stage in backward_stages:
    compute_done += stage.backward_ms
    returns_done.append(compute_done + stage.return_dkv_ms)
compute_done += local_backward_ms
backward_done = max(compute_done, *returns_done)

A more detailed model can represent serialization between transfers, gather streams, and hardware resource contention. The important invariant is that communication begins only when its input exists, and compute begins only when its dependencies are ready. The global objective uses the slowest participating rank, not the average rank.

Counting bytes also needs actual tensor geometry. In BF16 GQA, one KV token with H_kv heads, key dimension d_k and value dimension d_v occupies 2 H_kv(d_k+d_v) bytes. The Qwen attention shape used below has four KV heads and d_k=d_v=128, or 2,048 bytes per KV token. One 4,096-token fetch is 8 MiB before any additional buffers or replication. dKV transport may use a different accumulation dtype; its byte count must use that dtype rather than blindly copying the forward estimate.

Implementation anchor: ART context-parallel planner and runtime. Coefficients and search budgets describe this revision, not a claim of universal optimality.

06 / Change visibility, preserve the algebra

Trees, sliding windows, and attention sinks

The same staged attention algebra supports these cases, but storage addresses must not masquerade as positions or probabilities.

A tree mask is not an ordinary causal mask applied to the packed row. Physical position 8 follows completion A in storage, but A is not an ancestor of B. Position IDs also follow the root-to-leaf path. In our example, B's tokens at physical positions 7 and 8 have logical positions 4 and 5. That distinction affects rotary position embeddings as well as visibility.

For sliding-window attention (SWA), a query sees only a recent part of its logical history. If the window contains three tokens including the current token, query B8 at logical position 5 can see logical positions 3,4,5: physical tokens 3,7,8. Taking the last three physical addresses instead would return 6,7,8, leaking a sibling and dropping the correct root token.

The planner can intersect tree ancestry with the layer's window rule when counting work and requesting ranges. The local kernel receives the resulting mask. Smaller windows reduce arithmetic and often KV traffic, but they also reduce how much compute is available to hide communication. A model alternating global and windowed layers may therefore have very different bottlenecks in those two layer classes.

A learned sink is probability mass, not another token

Some models, including GPT-OSS, add a learned attention-sink logit per head. In this use of the term, the sink contributes to the softmax denominator but has zero value. It allows the head to assign some probability to “read nothing.” This is distinct from keeping the first few real tokens globally visible, another technique sometimes called attention sinks.

Suppose ordinary attention over visible tokens has output o and LSE L, and the sink logit is a. Including the sink rescales the token output by exp(L)/(exp(L)+exp(a)). The sink belongs to the whole query, not to every remote stage. Applying one copy in each of four stage denominators would silently multiply its mass by four and make the model depend on CP size.

ART can apply the sink once when composing the complete output, while retaining the ordinary local kernel and its LSE interface. Backward must propagate through that rescaling, including into the learned sink parameter. This small example illustrates a broader principle: preserve model semantics at the correct algebraic boundary, rather than independently applying a whole-model correction inside every partition.

Derivation: the global sink and its gradient

Let Z be the visible-token exponential mass and N its weighted value sum. An extra zero-valued sink of mass exp(a) changes o=N/Z to y=N/(Z+exp(a)). With L=log Z:

L_total = logaddexp(L, a)
w = exp(L - L_total)
y = w * o

for g = dJ/dy:
dJ/do = w * g
dJ/dL = w * (1-w) * dot(g, o)
dJ/da = -w * (1-w) * dot(g, o)

The token scores receive the LSE adjoint in addition to the ordinary attention-output adjoint. Applying the denominator correction without this gradient path would produce plausible forward outputs and wrong training gradients. Equivalently, treat the sink as one extra partition with output zero and LSE a, then use the general merge derivative.

Tree position handling is a separate invariant. An ancestor has one physical identity shared by descendants, while a descendant's logical offset depends on its path. Storage permutations may change physical indices, but they must preserve both ancestry and logical positions. Masks and rotary embeddings must use the latter where required by the model.

07 / Change how keys are selected

GLM-5.2: parallelize the search as well as the attention

A learned indexer first chooses the keys. ART distributes that choice, merges canonical token IDs, and gives a combined KV buffer to an efficient sparse-attention kernel.

Dense attention computes scores for every visible key in every attention head. GLM-5.2 uses a separate, cheaper learned indexer to choose a limited number of visible tokens, then performs its main attention only on those choices. Multi-head latent attention (MLA) stores a compressed representation of KV, reducing KV storage and transport relative to storing a separate expanded KV vector for every query head.

The model configuration behind these experiments has 78 layers and hidden width 6,144. Attention has 64 heads, a 2,048-dimensional compressed query projection, a 512-dimensional KV latent, and value dimension 256 per head. Its indexer has 32 heads of dimension 128 and selects up to 2,048 tokens per query. The first three MLP layers are dense; later layers have 256 routed experts plus a shared expert. The MLP and attention designs are independent reasons this model differs from an ordinary dense Transformer.

The indexer's score is itself a small multi-head computation. Each indexer head compares its projected query with a shared projected key, applies ReLU to that dot product, and contributes through an input-dependent head weight. Summing these contributions gives one scalar candidate score, with the model's scale factors included in the projected quantities and weights below. This is not the main attention head's softmax probability. Tree visibility first determines which candidates are eligible; the indexer then chooses among them.

index_score(i,j) = sum_h weight(i,h)
                         * max(dot(index_q(i,h), index_k(j)), 0)

selected_ids(i) = top_k visible j by index_score(i,j)

The expensive part is not only the final sparse operation. The indexer must inspect the query's visible candidates, score them, and select top-k. Its scoring and selection are separate from the softmax in the main attention. The architecture amortizes this work with IndexShare: a full-index layer computes routes and following shared-index layers reuse them. In this configuration the first three layers compute their own indices, followed by repeating groups of one full-index layer and three shared-index layers. Shared layers reuse token choices, not another layer's KV values.

hidden tokens
  -> Q / compressed-KV projections
  -> full layer: score candidates and choose token IDs
     shared layer: reuse preceding full layer's token IDs
  -> sparse MLA over the selected KV rows
  -> output projection and residual
  -> dense or mixture-of-experts MLP

The sparse kernel already takes a list of KV rows

This interface is the key to reuse. A sparse MLA kernel accepts queries, a KV buffer, and a per-query list of indices into that buffer. It does not need to know that the values came from different GPUs or that visibility originated in a prefix tree. ART can reorganize and remap the input without replacing all of the kernel's highly tuned arithmetic.

MLA's compression survives this boundary. ART folds the key expansion into the query projection, so the kernel compares a transformed query directly with the compressed KV latent plus its positional component. It accumulates a weighted sum in latent space; the value expansion happens afterward. It does not send an expanded 64-head KV tensor merely to run the distributed operation. That is both a memory saving and a reason to preserve this kernel interface carefully.

On a full-index layer, each scheduled candidate stage produces scores paired with canonical token IDs: identities in the packed tree, independent of the stage's temporary storage. The query owner merges these candidates into its global top-k. Then it assembles the required stage KVs into a combined buffer and maps each winning ID to that buffer's row. One sparse MLA call consumes the resulting list.

Why not call sparse MLA separately for every candidate stage? After selecting a fixed total of k keys, each stage may hold only a small and uneven part of them. Separate calls repeat launch, bookkeeping, and intermediate-output work. Combining the selected address space allows the kernel to see one normal sparse problem. Backward splits dKV using the saved buffer boundaries and returns contributions to their owners, just as in dense CP.

IndexShare makes canonical IDs especially important. Reusing temporary offsets from another layer or plan would confuse “row 17 in this receive buffer” with “token 17 in the input.” The former changes with placement; the latter is a stable model choice. Any routing tie rule must also remain independent of message arrival or rank order.

Where ART actually changed the kernels

The sparse kernels were adapted from Miles GLM and TileLang's DeepSeek-V3.2 work. Their GPU schedules are valuable starting points, not untouchable black boxes. ART added variable-length CP integration, canonical route handling, combined KV execution, supported TP-local head counts, and kernel changes where the original geometry was inefficient or incorrect under the pinned toolchain.

One important backward issue is atomic contention. Many queries may select the same shared-prefix key. They all contribute to its dK/dV, and parallel programs must add to common locations safely. Atomics provide that addition, but contending updates can serialize. ART used four FP32 accumulation shards for dKV followed by a reduction. This spends temporary memory and an extra reduction to reduce contention in the dominant kernel. It is a general response to shared-key fan-in, not a special rule for one prompt length.

Indexer work also suffered from launch shape. Grouping rectangles that share query ranges reduced 1,715 rectangle programs to 286 grouped-query programs in the recorded case. Making query/key extents runtime arguments removed repeated specialization as sequences changed. These changes affect different costs: grouping improves GPU work organization; dynamic extents remove compilation from changing-input execution. They should not be conflated into a single arithmetic speedup.

Other work repaired a pinned TileLang backward problem that could produce NaN dQ, handled invalid route sentinels, preserved the LSE log-base convention, and tuned SM100 dQ using its tensor-core instructions with explicit shared-buffer synchronization. Correctness at these interfaces is essential: a kernel with a faster but incompatible LSE convention breaks the same merge derivative we derived earlier.

Proof: stage-local top-k is enough to recover global top-k

Assume each visible candidate belongs to one stage and every stage uses the same total ordering: first by decreasing score, then the canonical tie rule. If candidate x is not in its stage's top-k, at least k candidates in that stage outrank it. Those k also exist in the global set, so x cannot be in the global top-k. Therefore the global winners are contained in the union of the stage-local top-k sets.

The owner can merge those sets without receiving a full dense score matrix. This does not make the indexer free: stages still have to compute the required scores. It also does not imply that the main sparse KV fetch is only k tokens total, because different queries select different keys and the union can be much larger.

Deduplicate any repeated candidate identities before applying this reasoning. Padding entries must not compete with real tokens. Stable selection order is necessary when tied scores straddle the k boundary, not just for aesthetically consistent output lists.

Derivation: why MLA can attend directly in latent space

For one attention head, let a token's compressed KV be column vector c_j. Ignoring the positional part momentarily, the head's expanded key and value are k_j=W_K c_j and v_j=W_V c_j. W_K and W_V are linear maps shared across token positions. Then:

q_i^T k_j = q_i^T W_K c_j
          = (W_K^T q_i)^T c_j

sum_j p_ij v_j = sum_j p_ij W_V c_j
              = W_V (sum_j p_ij c_j)

Transform the query once and perform the attention dot product in latent coordinates. Accumulate the attention-weighted latent vector, then expand it to the head's value dimension. The expansion commutes with a weighted sum because it is linear. We do not move it through softmax: the probabilities must still come from the correct transformed scores.

The positional contribution is retained separately. With an additional rotary query/key pair, the score is a sum of a latent dot product and a positional dot product. Concatenating the transformed latent query with the rotary query, and c_j with the rotary key, lets the kernel compute that sum as one dot product. The model's scale factor still follows its intended score convention, not an arbitrary rescaling based on the new stored width.

The sparse index list only restricts which j participate. It does not change either linear identity, so the same absorbed representation works across a prefix-tree CP stage layout. Backward differentiates the latent attention, query transform, and value expansion, while the selected-token routing follows the architecture's indexer contract.

08 / Change what represents the past

Gated DeltaNet: a recurrence need not become a rank pipeline

A token shard can compute its effect on an unknown incoming state. These effects compose, letting ranks do most of their local work concurrently.

Qwen3.5 mixes ordinary attention with Gated DeltaNet (GDN) layers. An attention layer keeps access to individual past keys and values. GDN compresses the past into a finite matrix state. That makes its token-dependent work linear in sequence length for fixed model dimensions, but a literal reading of its recurrence appears to introduce a sequential dependency at every token.

For one head, write the state S as a d_k by d_v matrix. A key k selects a direction in its key dimension, and k-transpose times S reads the value currently associated with that direction. Each new token has a query q, a key k, a value v, a decay alpha, and a write strength beta. First decay the old state, then correct its prediction of v in the direction k:

S_pre = alpha * S_previous
delta = beta * (v - S_pre^T k)
S_new = S_pre + k delta^T
y     = S_new^T q

All q, k, and v in this notation are column vectors. The superscript T means transpose, not sequence length. If the state already predicts v accurately, the correction is small. If it does not, the outer product k delta-transpose changes the relevant key direction. Alpha controls forgetting; beta controls the correction. This is not merely adding k v-transpose at every step, and not an interpolation that replaces the entire state.

The surrounding layer projects its inputs, applies a short causal depthwise convolution to the Q/K/V streams, normalizes Q and K, constructs the gates, and after the recurrence applies gated normalization and an output projection. A depthwise convolution filters each channel independently over nearby preceding tokens. These token layouts and short filters matter to runtime even though they are not the recurrence itself.

First parallelize within a GPU

We should not run the equations above as a Python loop over thousands of tokens. Flash Linear Attention (FLA) realizes the same recurrence using small chunks. Within a chunk, it expresses the interactions as triangular matrix operations suitable for GPU kernels; between chunks it carries the finite state. ART builds on these efficient gated-delta kernels. FLA implementation.

The important property is that a chunk's input-dependent preparation can be computed before its incoming state is known. It produces matrices that express both its outputs and its final state as affine functions of that incoming state. “Affine” means a linear transformation plus an additive term. This gives us a much better distributed algorithm than waiting for rank 0 to finish all its tokens, then rank 1, then rank 2.

Then parallelize across GPUs

For a whole rank-local shard of a chain, combine its chunk transformations into:

S_out = M * S_in + E

M: d_k by d_k       E: d_k by d_v

M describes how this shard transforms any prior state. E describes what it writes starting from zero. These depend on the shard's tokens, not on the actual state arriving from earlier shards. Every rank can therefore prepare its local token work and its summary (M,E) concurrently. It does not fetch the preceding ranks' Q/K/V to replay their recurrence.

Two summaries compose in order. If A runs before B, substitute A's output into B:

M_BA = M_B * M_A
E_BA = M_B * E_A + E_B

This composition is associative, although not commutative. A prefix scan computes the composition of all earlier summaries for every rank. It is the same algorithmic idea as cumulative sums, with affine composition replacing addition. After the scan, each rank knows the true initial state for its shard and applies it to the work it prepared locally.

The source snapshot uses doubling rounds: at distance 1, then 2, then 4, each rank incorporates an earlier aggregate. These are collective all-to-all exchanges with zero-count entries for uninvolved peers, not a rank-conditional chain of ad hoc sends. An extra shift makes the result exclusive, meaning “all shards before me,” and the final chain state is distributed where the tree needs it. Backward uses the corresponding suffix information in reverse order.

That detail explains both the benefit and the cost. A chain of N ranks does not require N full shard computations in series. But there are logarithmically many rounds of summary communication and matrix composition, plus boundary work. Summary size is independent of token count but grows with head count and squared key dimension. On short shards, it can be a substantial fraction of the whole operation.

The tree supplies a second kind of parallelism

Not every segment should be chained. If an entire independent family fits efficiently on one rank, a local execution avoids distributed summary costs. If one long root dominates the row, distributing that root can reduce the maximum rank time. When a root finishes, all its children inherit the same state and can run independently; at the next tree level, their children do the same.

ART represents these dependencies as a directed acyclic graph (DAG). For a dependency depth it batches compatible local work together and chained work together, rather than launching a separate recurrence for every family. Packed metadata uses one token dimension and segment offsets, so varying lengths do not require every segment to occupy the longest segment's padded width. The local and chain cases use the same mathematical operator, with different ownership of its state boundary.

Backward follows the DAG in reverse. Two children using one parent state contribute two gradients to it; those are summed before propagating through the parent. Within a chained segment, a rank's state gradient includes effects from later ranks as well as its own token outputs. Merely backpropagating each shard from a zero final-state gradient would lose the cross-rank dependency.

Convolution needs a halo, not the whole prefix

A causal filter of width K needs at most K-1 preceding input tokens to begin a shard. Those boundary tokens are called a halo. If a shard is extremely short, its halo may span more than one earlier rank. At a tree fork, the children begin from the parent's tail, not the tail of a sibling adjacent in storage.

ART's true variable-length convolution handles the packed segments, activation, and state boundary. Communication supplies the needed tails; backward returns and accumulates gradients for their duplicated uses. This avoids converting a ragged family into a large padded batch merely to call a rectangular convolution. The custom layout and convolution kernels are useful because they remove real memory work and launches around the already-efficient recurrent kernel.

The remaining planner choice is economic: does saved token compute exceed layout exchange, summaries, scans, and parent-state traffic? GDN's runtime model includes these terms and scales state sizes with actual head/key/value dimensions. Its fit uses more than the 35B shape, including 9B and 397B. It is still an empirical model with bounded search, not a guarantee of globally optimal plans. A fixed “chain above this many tokens” rule would miss both model-size differences and the other work competing for each rank.

Consecutive GDN layers can retain a GDN-friendly token ownership, an island, rather than exchange back after every layer. The residual stream and tokenwise modules must agree on that layout. Attention-to-GDN boundaries perform the required redistribution; TP sequence-parallel split/gather operations must preserve the same token order through the island. Layout is part of the layer contract, including recomputation in backward.

Derivation: from the token delta rule to the chunked FLA realization

This derives the chunk form for one head using a d_k by d_v state, matching the orientation above. Let a chunk have c tokens numbered 0 through c-1. The chunk-start state S_start is unknown during preparation. q_i and k_i have d_k entries; v_i and delta_i have d_v entries; beta_i and alpha_i are scalars. Define log-decay ell_i=log(alpha_i) and cumulative G_i=sum_{t=0}^i ell_t.

S_pre_i = alpha_i S_(i-1)
delta_i = beta_i (v_i - S_pre_i^T k_i)
S_i = S_pre_i + k_i delta_i^T

Unroll S_pre_i. The incoming state is decayed by tokens 0 through i. A write at j<i is decayed by tokens j+1 through i:

S_pre_i = exp(G_i) S_start
        + sum_{j<i} exp(G_i-G_j) k_j delta_j^T

Substituting this into the delta equation gives a triangular dependency among the deltas:

delta_i^T = beta_i [v_i^T
  - exp(G_i) k_i^T S_start
  - sum_{j<i} exp(G_i-G_j) (k_i^T k_j) delta_j^T]

Stack row vectors into matrices K [c,d_k], V [c,d_v], and D [c,d_v], where row i of D is delta_i-transpose. Let B be the diagonal c by c matrix of beta values. Define a strictly lower triangular matrix P and a decayed key matrix K_start:

P[i,j] = exp(G_i-G_j) * dot(k_i,k_j), for j<i
P[i,j] = 0, otherwise
K_start[i,:] = exp(G_i) * k_i^T

D = B (V - K_start S_start - P D)
(I + B P) D = B (V - K_start S_start)

The diagonal of I+B P is one. FLA uses a small triangular inverse and matrix products, not a general dense inverse over the whole sequence. If A=(I+B P)^(-1), define:

U = A B V           [c,d_v]
W = A B K_start     [c,d_k]
D = U - W S_start   [c,d_v]

U and W do not depend on S_start. They are the prepared token work we can compute before a distributed prefix scan supplies that state. Chunk size is a kernel scheduling parameter; the expensive square object is c by c, not total-sequence-length squared.

Recover both the final state and every output

Let R have row j equal to exp(G_last-G_j) k_j-transpose. Then all in-chunk writes propagated to the end give:

S_end = exp(G_last) S_start + R^T D
      = [exp(G_last) I - R^T W] S_start + R^T U

M = exp(G_last) I - R^T W
E = R^T U

That is the affine summary, obtained without knowing S_start. It includes forgetting and the delta correction. Replacing M with a scalar decay would discard the key-dependent rank-one updates and would implement a different model.

Outputs read the state after each token's own write. Define Q_start row i as exp(G_i) q_i-transpose, and a lower triangular matrix C including its diagonal:

C[i,j] = exp(G_i-G_j) * dot(q_i,k_j), for j<=i
Y = Q_start S_start + C D
  = (Q_start - C W) S_start + C U

Any model-specific query scaling is absorbed into Q in these equations. The output formula again separates prepared local work from a correction using the incoming state. FLA's implementation divides these operations among kernels and stores the intermediates useful for its backward; the derivation is not a recommendation to allocate every matrix in Python.

Why this remains linear in sequence length

For fixed head dimensions and fixed c, every chunk does bounded-size triangular and matrix operations, then carries a fixed-size state. Doubling the number of tokens doubles the number of chunks rather than quadrupling a global score matrix. Constants can still be substantial: multiple kernels, state reads/writes, and low arithmetic intensity can make a linear operator slower than a well-tuned quadratic operator at moderate lengths.

Numerically, exp(G_i-G_j) is a product of intervening decays. For j<=i and nonpositive log-decays, it is at most one. Computing the difference of cumulative logs avoids dividing two separately underflowed products. Exact-real-arithmetic equivalence does not remove rounding sensitivity in dot products, triangular work, or different state-composition orders. Those need explicit forward and gradient validation, not an “it is linear” assumption.

Derivation: affine scans, reverse gradients, and summary cost

Represent f(S)=M S+E by (M,E). For chronological transforms a then b, define b composed with a as (M_b M_a, M_b E_a+E_b). Applying a third transform c on either parenthesization gives:

M_c M_b M_a S
  + M_c M_b E_a + M_c E_b + E_c

Thus composition is associative. The identity is (I,0), which also represents an empty shard. A rank with no real tokens must still participate in the scan protocol; identity arithmetic and zero-sized transport are distinct parts of that contract.

For four scalar examples f_0(s)=0.5s+1, f_1(s)=0.8s+2, f_2(s)=0.6s-1, and f_3(s)=0.9s+0.5, the complete composition is 0.216s+1.112. From s=0, incoming shard states are 0, 1, 2.8, and 0.68. They can be obtained by a prefix scan of the four summaries; no rank needs an earlier rank's token array.

For backward, write a shard's outputs as Y=F S_in+U and its end state as S_out=M S_in+E, where F abbreviates its prepared output response. Given output gradient dY and an end-state adjoint dS_out:

dS_in = F^T dY + M^T dS_out

Appropriate tensor contractions replace the shorthand matrix products for all token outputs. This is an affine dependence on the incoming backward state, so suffix summaries can propagate future effects. Local kernel backward additionally differentiates its prepared quantities to produce dQ, dK, dV and gate gradients. A state-gradient scan alone is not the entire backward pass.

With H local value heads, an FP32 forward summary contains H d_k(d_k+d_v) elements. For H=32 and d_k=d_v=128, that is 4 MiB per chained segment. A recurrent state is 2 MiB. These are much smaller than a long token shard, but not negligible if a bucket contains many chains. Doubling scan rounds avoid every rank storing every other rank's summary, while adding communication latency and composition work at each round.

The implementation uses an exclusive-prefix shift and final-state distribution in addition to the doubling rounds. Backward similarly includes suffix and boundary operations. A performance estimate that prices only log2(N) arithmetic multiplications, or only the bytes of one state, understates the real layer.

09 / Move the partition instead

Mamba-2: each rank gets the whole tree for fewer heads

The qualified Nemotron path uses an all-to-all transpose from token shards to head shards, preserving the native SSD kernel instead of using GDN's distributed summary implementation.

Mamba-2 is also recurrent, but it is not GDN with another name. Its selective state-space model constructs an input-dependent write and read around a decaying state. Within a head, the decay has a simpler structure than GDN's key-dependent matrix correction. Mamba-2's state-space duality (SSD) connects this recurrence to structured matrix operations, enabling efficient chunked GPU execution. Mamba-2 paper.

In a simplified per-head notation, x is a vector of channels; B and C are state write/read vectors; dt determines the discretized time step. The head's learned decay parameter and dt produce a scalar decay a. A state H maps state coordinates to channels:

H_t = a_t H_(t-1) + x_t b_t^T
y_t = H_t C_t + D_skip * x_t

b_t includes the input/time-step scaling in this notation. The full layer projects x, B, C, dt, and a gate z, applies a short convolution to the appropriate streams, runs SSD, and applies gated normalization and output projection. Several heads can share B/C through groups, so those projected widths need not equal the full number of heads times state dimension.

The Nemotron Nano configuration studied here contains 52 blocks: 23 Mamba, 23 MoE, and six attention blocks. Its Mamba layers have 64 heads, eight B/C groups, state dimension 128, and convolution width four. These independent heads offer another distributed decomposition: instead of splitting a head's recurrence across ranks, give a rank fewer heads but all physical tokens.

What crosses the network

The input projection runs on the original token owners. ART then partitions projected x/B/C/dt by recurrent head assignment and uses one all-to-all to assemble each destination's full-token, partial-head streams. An all-to-all lets every rank send a different slice to every other rank. This exchange is a transpose of the token-by-head ownership grid, not an all-gather that replicates every head's tokens everywhere.

The gate z is not needed by SSD itself. It remains on token owners. After the recurrent computation, the reverse all-to-all brings each token's output head slices home, and gated normalization/output projection proceed in that original layout. Backward reverses the two transposes and accumulates any replicated grouped B/C contributions.

This differs deliberately from our dense attention strategy. There, queries remain token-sharded while needed KV visits them. Here, the independent head axis lets the recurrence run locally across all tokens. The cost is moving the projected recurrent streams and the output, and the benefit is leaving the native SSD kernel in control of the full sequence for its heads.

What the tree wrapper changes

After redistribution, each rank still sees a tree, not one ordinary causal array. ART computes the physical tree's convolution once for its channels, gathers recurrent inputs into tree-aware scan buckets, and supplies the correct parent states. The numerical core is the official mamba_ssm 2.3.2.post1 SSD scan. Custom Triton kernels handle permutation, gathering, assembly, and the corresponding gradients around it.

The native chunk interface also shapes state reuse. Complete shared chunks can hand their states to descendants; an unaligned shared suffix is replayed in the child's scan so the native kernel sees its expected chunk realization. That replay is bounded by the chunk size, not the entire prompt. It is a real overhead and must be counted, but it is not the central explanation of scaling. The dominant design choice is the token/head transpose and reuse of native SSD.

There are limits. A head shard must have a supported width, so CP size cannot grow independently of the number of available heads. If several rank shards need the same B/C group, those narrower streams are replicated and their gradients summed. Full-token metadata is present per recurrent rank, and poorly chosen bucket shapes can introduce padding or extra layout work. “Every rank gets fewer heads” is not proof that every allocation is exactly divided by CP.

This is also why we do not call Mamba's implementation “the GDN scan path.” Both exploit recurrent structure, and both preserve shared-prefix states, but their network interfaces are different. The measured Nemotron implementation has a qualified CP2 training result and pipeline comparison; we do not yet have a matching CP1/2/4/8 curve from which to claim the same scaling as dense attention.

Derivation: the transpose, grouped streams, and native SSD reuse

Ignore TP for a moment. With N CP ranks, T total tokens and H heads, token ownership starts at roughly [T/N,H] per rank. An all-to-all sends each destination its H/N head slice for all source token shards. The destination receives [T,H/N]. Both contain T H/N token-head entries, even though only the latter permits a local recurrence through the complete token order.

rank r before: tokens owned by r, heads 0 ... H-1
send to rank j: those tokens, head slice j
rank j after:  all tokens, head slice j

reverse exchange:
send each token owner's rows back, then concatenate head slices

A permutation's derivative is its inverse. The independent x and output-head streams therefore need transposed movement, not gradient reduction across duplicate full copies. B/C are different when groups are shared across head shards: one source entry can feed several consumers. Its derivative is the sum of those consumers' contributions. Leaving this reduction out would make forward look correct and backward depend on CP size.

For the scalar-decay state equation, unrolling a chunk gives a weighted sum of writes with weights equal to products of intervening a_t. SSD exploits the structure of this matrix instead of forming a general dense sequence-by-sequence attention matrix. ART does not need to invent another SSD realization to use CP; it supplies full token order for a head shard and the correct tree boundary states to the established kernel.

The z gate has no role in that recurrence, so transporting it would add bytes without enabling any earlier compute. This is an example of choosing the communication boundary from actual data dependencies rather than indiscriminately exchanging either all hidden activations or every projected channel.

10 / Account for the whole rank

Which memory scales, and which does not?

CP divides token-dependent storage. It does not, by itself, divide model weights, eliminate communication buffers, or make every architecture's temporary state scale identically.

Suppose a residual tensor has T tokens and hidden width H. With balanced token ownership across N ranks, each rank stores about T H/N elements. Many intermediate activations, Q/K/V projections, and tokenwise gradients have the same dependence. At fixed total T, CP can reduce them. If T grows with N in weak scaling, they can stay approximately constant per rank.

Parameters behave differently. A rank that owns fewer tokens still needs the weights used on those tokens. CP alone generally replicates dense weights across its ranks. TP, EP, PP, optimizer sharding, or weight offload may address that memory. In a CP8/EP8 MoE run, lower expert-weight memory comes from EP, not from an unexplained property of CP. Adding both axes together is useful, but attribution matters.

Activation checkpointing, also called recomputation, saves fewer intermediate activations and recomputes them during backward. It can combine with CP. The recomputed layer must use the same tree, ownership, and communication contract as the original forward. A cached mutable “current layout” that changes before recomputation can corrupt results even if the first forward looked correct.

Why CP can be an attractive alternative to more TP or PP

Increasing TP splits each matrix multiplication further. That can reduce local matrix efficiency and requires collective results at linear-layer boundaries. Depending on the model, moving compressed KV for attention can be cheaper than moving hidden-width partial linear results repeatedly. CP also leaves larger local channel dimensions for tokenwise matrix multiplication. These are reasons to try it, not a claim that CP always sends fewer bytes on every architecture.

PP keeps each GPU busy only when its pipeline stage has a microbatch available. Long packed sequences consume substantial memory, limiting how many microbatches we can keep in flight. Hybrid models also make stages hard to balance: an attention block, a GDN block, and an MoE block need not take equal time. Bubbles and uneven stage time can then outweigh small pipeline transport costs.

CP works within one packed microbatch and can use all ranks on its token-dependent work. That makes it particularly valuable when there are too few independent packed microbatches to fill a deep pipeline. Data parallelism remains valuable once enough separate work and enough memory are available; it avoids the within-sequence communication entirely. The right conclusion is to choose axes according to the limiting resource, not to treat one topology as universally best.

Finally, distinguish allocated memory, live tensors known to the allocator, from reserved memory, the allocator's retained blocks. Report the peak across ranks. Different completion lengths and concurrent buffers can change fragmentation and peak reservation without changing the mathematical tensor count. A layer-memory estimate is useful for planning, but a real training run is the proof that the job fits.

11 / Put the mechanisms against measurements

How close do we get to the scaling target?

Dense attention is very close after its first distributed step. Sparse MLA has a larger fixed CP cost. GDN scales usefully but has a more exposed scan cost. The distinctions are visible in the measurements.

The plots below show time relative to each series' CP1 time. Ideal weak scaling is a horizontal line at 1: N times the GPUs process roughly N times the physical work in the original time. A ratio of 1.2 at CP8 means 8/1.2, or about 6.7 times, the aggregate throughput of CP1, not a 20% throughput gain. Scaling efficiency is the reciprocal of the time ratio for matched weak-scaling work.

12 / What makes a result transferable

Measure the computation real training will execute

A good local kernel result is necessary. It is not sufficient until changing trees, gradients, preparation, memory, and the surrounding model agree with it.

The experiments use several levels of measurement for different questions. Operation labs make ownership, stages, kernel time and communication observable without full-model setup. Stacked-layer benches expose per-layer repetition, layout transitions, and specialization on changing inputs. Isolated backend training adds real parameters, experts, optimizer/adapter work, recomputation and model memory. Live-pipeline checks finally measure how much of that rate survives input supply and job boundaries.

The throughput tables report physical packed tokens per second, not generated tokens or trajectories per second. A shared prefix contributes physical tokens even when it has no direct loss. When comparing different packing schemes, count completed trajectories or the same training objective as well: removing redundant prefix copies can improve useful throughput while reducing the number of physical tokens executed.

We keep instrumentation on the lab or harness side. Nsight/NVTX ranges are useful for explaining a trace, but heavy per-module timing and memory hooks can themselves change throughput. A clean throughput run uses the intended compilation setting and avoids those hooks. A diagnostic run supplies attribution, with its overhead and measurement scope stated separately.

Changing inputs are part of the performance contract

A kernel can be fast on a warmed input and unusable if it recompiles whenever the next completion has a different length. Token counts, segment counts, and variable total extents should therefore be runtime inputs where possible. Static model dimensions and a finite set of execution roles can still specialize. The relevant question is whether warmup covers those roles in a reasonable number of independent examples, not whether an exact replay hits its cache.

In the dense source checks here, sixteen measured trees were distinct from the warmup trees. The fixed control deliberately repeated geometry, while varied workloads sampled lengths afresh. The cold-role example above is why four warmup inputs were not sufficient evidence on their own. A benchmark should record the per-sequence time series and new compilations, not discard an arbitrary number of slow samples until a preferred average appears.

Correctness needs more than one output comparison

Packed-versus-flattened tests establish that branches cannot read siblings and shared computation matches independent trajectories. Topology oracles compare canonical outputs and gradients across parallel layouts. Tracing must reconstruct original token identity before comparing; otherwise a storage permutation looks like a model error. Exact routing checks catch sparse-index changes that a mean output tolerance could miss.

For recurrent layers, tests also need parent-state gradients, empty participants, short segments, long chains, and recomputation. A rank skipping a collective is a protocol error even if it has no local arithmetic. Conversely, a large relative gradient error should not be dismissed because the tensor's absolute values are small. Correctness is the algebra and its complete distributed realization.

Low-precision kernel outputs need dtype-appropriate tolerances, but tuning those tolerances is not a performance optimization. The useful optimization target is preserving the intended math while eliminating needless movement, launches, replication, and serial dependencies. This is why the kernel-reuse boundary is important: we keep mature arithmetic where it works and modify the surrounding organization, or the kernel itself, only where evidence identifies a real limitation.

The common idea, after the differences

There is no one “CP primitive” that explains all four implementations. Dense attention brings KV to query owners and merges normalized results. GLM first merges a learned choice of token identities, then runs sparse attention over remapped KV. GDN composes transformations of the recurrent state. Mamba redistributes the independent head dimension so native SSD can process each head's tree locally.

What they share is a method: start from the information dependency, find a compact interface to the efficient local computation, preserve token and gradient ownership, and schedule the remaining communication against actual compute. The planner must model that execution, not a convenient surrogate such as token balance alone. The benchmark must measure that execution on changing inputs, not just its most cache-friendly snapshot.

The original motivation was a longer useful row. Prefix trees remove duplicate prompt work; CP makes room to process more of the remaining trajectories together. The evidence shows this can be a strong throughput strategy as well as a memory strategy, including across nodes. Understanding why requires both halves: the algebra that permits partitioning, and the execution details that keep partitioning from becoming expensive.

Definition: useful MFU, and why a high scaling efficiency can coexist with low MFU

Model-FLOP utilization divides a model-work estimate by elapsed time times the machine's peak arithmetic rate at the stated precision. Here “useful” work excludes replaying shared prefixes as though every trajectory were flattened. If a model executes one physical prefix, counting it sixteen times in the numerator would artificially inflate MFU.

useful MFU = useful model FLOPs
           / (elapsed seconds * total GPU peak FLOPs/second)

weak-scaling efficiency = time_at_base / time_at_N
  when useful work and GPU count both grow by N

They measure different things. A memory-bound kernel can use a low fraction of peak tensor-core arithmetic while scaling almost perfectly across GPUs. Sparse gather patterns, atomic reductions, small matrix geometry, launches, and state traffic can all limit MFU without invalidating weak scaling. Conversely, high arithmetic utilization on a rank is not helpful if other ranks are idle or if the work is redundant.

Checkpoint recomputation and kernel bookkeeping consume real time. A useful-work numerator should not inflate itself to reward that overhead. Comparisons must use the same FLOP convention, layer count, precision and clock assumptions. The numbers here are reported under their source experiments' useful-work convention, rather than treated as universal percentages comparable to every published MFU.
