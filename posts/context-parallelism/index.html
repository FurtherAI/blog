Scaling the Tree

Context parallelism for prefix-tree attention, learned sparse attention, and linear recurrent layers, from one H200 to two nodes.

August 2026 · 36 minute read

I started the CP project with three hypotheses: it could move less data than tensor parallelism, hide that communication behind the operation it serves, and lower memory per GPU. The most exciting possibility came from prefix-tree packing. Once a shared prompt is stored once, a little more physical row capacity can hold many more leaves and therefore many more trajectories per forward-backward pass.

My canonical 5K + 16x100 system-prompt workload barely benefits from that capacity effect: both the prompt and generations are short for a 35B model on two H200s. Long shared context, long rollouts, or a model that can fit only a small row under TP are different. What surprised me was that CP also scaled much better than TP even after excluding prefix-tree reuse. At four to eight ranks it was ahead in both memory and throughput; across two nodes, CP_N + EP_N remained the best topology we tested. Only after reaching the minimum model-parallel width did data parallelism become the better axis to add. This post develops the algorithms behind that result, including engineering work that moved at a pace only possible with Codex, and then shows where the time and memory went.

Context parallelism, or CP, divides tokens across GPUs. That definition sounds routine until the tokens form a tree. A query may attend to its ancestors but not its siblings. Completions have different lengths. Some models use a learned sparse indexer before attention. Others replace attention layers with a gated recurrence or Mamba-2. The same physical tree needs three genuinely different distributed algorithms.

The result was stronger than the memory fix we expected. In matched GLM-5.2 training, doubling from eight to sixteen H200s and doubling the packed row from 64K to 128K retained 94.6% raw weak-scaling throughput. On a cleaner medium-long workload it retained 98.9%. At fixed work, the CP-only topology was 27% to 39% faster than the tested pipeline-parallel alternatives. CP did not merely make the row fit; it became the most efficient way to grow it.

The useful unit is a tree

Consider a prompt with length P and m sampled completions with lengths C_i. Flattened training stores the prompt once per completion. A prefix tree stores it once in total: 

flattened tokens = m * P + sum(C_i)
tree tokens      =     P + sum(C_i)
saved tokens     = (m - 1) * P

The attention saving is larger than the token count suggests. The prompt's causal prefix-prefix triangle is also computed once instead of m times, saving roughly (m - 1) * P * (P + 1) / 2 attention pairs. A long shared context plus long rollouts fills a row quickly with useful new tokens, which is exactly where adding CP ranks can translate into more trajectories per forward-backward pass.

Derive the trajectory-capacity gain

With equal completion length C and row capacity S, flattened sequences fit floor(S / (P + C)) trajectories. A tree pays P once, then fits floor((S - P) / C). With a 24K root, 8K completions, and a 64K row per rank, CP1 fits five tree leaves versus two flattened trajectories. CP8 grows the row to 512K and fits 61 tree leaves versus 16 flattened trajectories.

Weak scaling, not benchmark multiplication

ART's benchmark workloads scale by adding families until a larger row is full. They do not make one family's prompt and every completion N times longer at CPN. That distinction matters: real training accumulates more prompts and rollouts, with independently varying completion lengths. Fixed 5K + 16x100 is a useful kernel control. Varied short, dominant-prefix, medium-long, ragged depth-three, and true long-completion trees test the planner's generality.

From zigzag to arbitrary work plans

Causal attention is already a load-balancing problem before trees enter the picture. If four ranks each own one contiguous quarter of a sequence, rank 0 evaluates only the top-left of the causal triangle while rank 3 evaluates almost the whole width. Ring-attention systems commonly repair this with a zigzag: split the row into eight chunks and assign owners 0,1,2,3,3,2,1,0, pairing cheap early queries with expensive late queries.

The key inspiration from MagiAttention was to stop treating a sequence as the indivisible scheduling unit: break attention into distributable query-key work and let a planner decide where it runs. ART did not import Magi's FULL/CAUSAL slicing, FFA CUDA, GroupCast, GroupReduce, symmetric-memory transport, or Megatron fork. The exact ART mask can describe arbitrary tree visibility. Its compact tree builder often emits full ancestor intervals and causal self intervals because those are the natural geometry of a tree, not because the executor is restricted to those two global shapes. 

tree = parse_prefix_tree(group_ids, parent_ids)
chunks = contiguous_chunks(tree.physical_order, target=512)
pair_work[q_chunk, k_chunk] = count_visible_pairs(tree, chunks)

owners, waves = search_assignments(
    chunks,
    pair_work,
    measured_kernel_throughput,
    exchange_bandwidth,
    launch_and_range_costs,
)
rank_plan = materialize_local_stages(owners, waves, exact_mask=tree)

Contiguous chunks are planner atoms, not an attention restriction. Searching every subset of individual tokens would be exponential and would produce thousands of tiny transport ranges. Chunking bounds the candidate count and keeps gather/scatter metadata compact. The ownership vector itself is unrestricted: one rank may receive any collection of chunks, contiguous or not. The planner converts that assignment into a local stage and a bounded number of remote waves, each carrying exact query ranges, KV ranges, and mask metadata.

Forward: move KV while local attention runs

Every rank starts with the hidden states for its assigned physical tokens. The planner specifies the query ranges it owns, local KV ranges, and remote KV ranges for each stage. The executor launches every remote KV exchange, gathers remote-stage queries on a side CUDA stream, and immediately runs the local stage. As remote receives complete, it runs ready stages rather than waiting for a fixed source order. 

remote = launch_all_kv_fetches(plan)
local  = run_attention(gather_q(local_stage), local_kv, local_mask)

partials = [local]
while remote.pending:
    for stage in remote.ready_or_wait_one():
        partials.append(run_attention(gather_q(stage), stage.kv, stage.mask))

output, lse = exact_stage_merge(partials)
Why separate attention stages merge exactly

Let stage a return normalized output O_a and log-sum-exp L_a; stage b returns O_b, L_b. Their union is: 

L = logaddexp(L_a, L_b)
O = exp(L_a - L) * O_a + exp(L_b - L) * O_b

Each coefficient is that stage's share of the global softmax denominator. The operation is associative, so changing stage order or rank assignment changes rounding, but not the mathematical attention. ART accumulates BF16/FP16 stage outputs and LSE in FP32 and uses a fused Triton backward for this merge.

Backward returns gradients to their owners

ART records each stage's local inputs and the minimal merge tape. Backward walks that tape in reverse, obtains each stage's output and LSE gradients, invokes the attention backward, scatter-adds dQ into query ownership, and sends dK/dV through the exact inverse range plan. Empty ranks still participate in the collective wave ordering. Skipping a zero-row collective is not an optimization; it is a deadlock.

What ART wrote here

The local attention math is upstream FlexAttention/FlashAttention. ART's work is the exact tree-mask and chunk-work builder, runtime cost planner, cached sparse block metadata, NCCL range exchange, ready-stage scheduler, head-major Triton gather/reduce, FP32 exact merge, fused merge backward, and its Megatron/autograd integration.

One executor, more attention semantics

Sliding-window attention and attention sinks look like small model details, but both expose easy distributed mistakes. ART keeps one CP executor and inserts each semantic rule at the only layer where it is globally valid.

Sliding windows use logical positions

Packed offsets have no semantic meaning across branches. Two neighboring physical tokens may belong to unrelated leaves, while a parent token far away in storage can be nearby in one branch's logical sequence. ART carries input_pos through the CP plan, builds conservative sparse block topology from each block's logical-position bounds, and leaves partial boundary blocks to the exact FlexAttention predicate. This removed an earlier token-by-token CPU refinement without introducing an SWA-specific executor.

The sink is global, once

An attention sink is an extra logit in the denominator, not another KV row. If every remote stage included it, a query with four stages would count four sinks. ART first merges all ordinary stage LSEs, then performs one logaddexp(global_lse, sink) and rescales the output. Its backward returns the exact gradient for the per-head sink parameter. This is used by GPT-OSS and DeepSeek V4 without creating a second CP implementation.

GLM-5.2: distribute the learned index, too

GLM-5.2 is a 78-layer hybrid of sparse multi-head latent attention and MoE. Hidden width is 6,144; attention has 64 heads, a 2,048-wide compressed query, a 512-wide compressed KV latent, and 256-value dimensions per head. The first three MLPs are dense; the remaining layers route into 256 experts plus one shared expert. Before sparse MLA, a learned 32-head indexer scores every visible candidate and selects 2,048 raw token IDs for each query.

Running that indexer in all 78 layers would be expensive. Layers are grouped into IndexShare runs: a full layer computes routes, and the following three shared layers reuse them. The first three layers are all full; after that, the pattern repeats one full plus three shared layers. Context parallelism therefore has two coupled jobs. It must distribute the candidate search on full layers, and it must preserve a canonical route object that later layers can reuse independent of rank placement.

That explicit-index interface is the important architectural affordance. ART does not need to rewrite a complex sparse-attention kernel to understand prefix trees or distributed stages. The dense CP plan fetches the exact KV ranges visible to a query owner. Each stage emits candidate scores paired with immutable global token IDs. The owner merges candidates with stable score-descending, ID-ascending ordering, concatenates the stage KVs, remaps winners to offsets in that buffer, and calls sparse MLA once. Backward splits dKV at saved stage boundaries and returns each part to its owner.

The single combined call was a substantial implementation change. The first version ran one sparse kernel per communication stage. At CP2, sequence 1024, top-k 128, combining stages reduced indexer plus attention time from 4.525 ms to 3.414 ms and peak allocation from 0.415 GiB to 0.243 GiB: 24.6% faster and 41.3% less memory. It also made the execution model cleaner, since the sparse kernel sees one canonical route space regardless of the plan.

Kernel adaptation, explicitly

upstream → ART production

ART's TileLang sparse-MLA kernels are adapted from Miles GLM and TileLang's DeepSeek-V3.2 work. The adaptation was not a rename. The upstream shared-memory backward produced NaN dQ with the pinned TileLang revision, and its vector atomic helper predated a TileLang fix. ART validated a scalar-atomic schedule, added a discarded sentinel KV row for invalid routes, and retained natural-log LSE at the public API while using base-2 exponentials internally.

Why canonical raw IDs are a correctness requirement

A stage-local row number is not token identity. The same raw token can occupy a different concatenated offset under another CP plan. Top-k must therefore compare (score, raw_token_id), including the model's stable tie rule, before converting winners to storage offsets. Otherwise two mathematically equivalent rank assignments can select different keys. ART's correctness tests require exact route IDs even when BF16 output and gradient checks use tolerances.

Recurrent layers turn the tree into a DAG

Attention stages can run in almost any order because their softmax summaries merge. A recurrent child cannot start until its parent's final state exists. The same prefix tree is therefore an execution DAG: roots precede children, siblings can run together, and a segment split across ranks needs the state produced by its preceding shard.

ART deliberately shares only the model-neutral tree parser: canonical segment ranges, parent indices, and depth. GDN and Mamba then build different plans because their state and communication algebra are different. A large generic recurrent executor would hide those distinctions without removing any real complexity. 

tree = parse_recurrent_prefix_tree(group_ids, parent_ids)

gdn_plan   = plan_token_shards_and_affine_scans(tree, attention_layout)
mamba_plan = plan_head_shards_and_scan_phases(tree, attention_layout)

GDN: summarize a token shard

Qwen3.5's gated delta network has two stateful operations. A small causal convolution needs the previous K - 1 projected tokens. The gated-delta recurrence carries a matrix state per head. Short siblings are often best as local forks: run the parent once, fan out its final state, and batch all children at that depth. Long segments can be split across ranks.

Splitting does not mean rank 1 waits while rank 0 loops over every token. FLA's 64-token formulation turns local recurrence into triangular dense work. A complete rank-local shard is affine in its incoming state: 

S_out = M * S_in + E

(M_B, E_B) after (M_A, E_A)
  = (M_B * M_A, M_B * E_A + E_B)

Every rank computes its local token-heavy summary in parallel. A distributed prefix scan composes the summaries before it to recover its exact initial state; a suffix scan does the analogous job for backward state gradients. Causal convolution exchanges only the K - 1 boundary tails, with reduce-scatter as the backward transpose of the forward gather.

Derive the gated-delta chunk and affine CP scan

Qwen projects input x into query, key, value, output gate, write strength, and decay streams. A depthwise causal convolution of width four runs over q/k/v, then q and k are L2-normalized: 

beta_t     = sigmoid(b_t)
log_alpha_t = -exp(A_log) * softplus(a_t + dt_bias)
alpha_t    = exp(log_alpha_t)

S_pre_t = alpha_t * S_(t-1)
d_t     = beta_t * (v_t - k_t^T S_pre_t)
S_t     = S_pre_t + k_t d_t^T
y_t     = q_t^T S_t

The correction is rank one in key space. It does not replace the whole state with outer(k_t, v_t). A serial loop is suitable for one-token decode but not training, so FLA evaluates fixed 64-token chunks with triangular matrix work.

For one chunk, let G_i be cumulative log-decay through token i. Unrolling the state before token i gives: 

S_pre_i = exp(G_i) S_start
          + sum_(j<i) exp(G_i - G_j) k_j d_j^T

Stack the 64 token deltas into D. Let B be diagonal beta, and let the strictly lower-triangular matrix P[i,j] = exp(G_i-G_j) * k_i^T k_j for j<i. Then: 

(I + B P) D = B (V - K_decay_start S_start)

A = (I + B P)^-1
U = A (B V)
W = A (B K_decay_start)
D = U - W S_start

I + BP is lower triangular, so this is a small triangular solve, not a general inverse. The chunk end state is: 

S_end = exp(G_last) S_start
      + sum_i exp(G_last - G_i) k_i d_i^T

Because D is affine in S_start, an entire contiguous rank shard is also affine: 

f_i(S) = M_i S + E_i

f_B(f_A(S)) = (M_B M_A) S + (M_B E_A + E_B)

Composition is associative. Every rank computes (M_i,E_i) from its own tokens in parallel; a distributed prefix scan returns the composition before each rank, which yields its exact starting state. Backward uses the transpose structure in reverse, with a suffix scan for final-state gradients. No rank replays another rank's token recurrence.

Custom GDN kernels

FLA supplies the gated-delta math and underlying chunk kernels. ART adds a true-varlen causal convolution plus GELU/SiLU forward and backward, compact segment gather/scatter, recurrent-input preparation, convolution tail scans, an FLA CP wrapper that exposes initial and final states, and autograd-aware all-to-all at GDN-island boundaries. Token and segment counts are runtime arguments so changing completions reuse compiled binaries.

Nemotron Nano Mamba-2: shard heads instead

NVIDIA Nemotron 3 Nano 30B-A3B interleaves 23 Mamba mixers, 23 MoE layers, and six standard-attention layers in an exact 52-layer schedule. Its Mamba mixer has 64 state-space heads, eight groups, state size 128, chunk size 128, and a width-four causal convolution. Unlike GDN, its clean CP partition is over heads rather than tokens. 

projected, _ = mixer.in_proj(hidden_states)
gate = projected[..., :inner]                 # remains on token owner
recurrent = a2a(projected[..., inner:])        # x, B, C, dt only
recurrent = physical_tree_conv(recurrent, plan)
recurrent = mamba_chunk_scan_combined(recurrent, fp32_state=True)
local = inverse_a2a(recurrent)
return mixer.out_proj(mixer.norm(local, gate))

ART did not replace the SSD math. It pins mamba_ssm 2.3.2.post1's mamba_chunk_scan_combined and wraps the pinned native causal-conv forward/backward. The original kernel work is around the tree: Triton pack/unpack for variable all-to-all, fused scan-input gathers, repeated-token gradient reduction, row/output assembly, and runtime token extents that do not specialize when completion lengths change. The plan runs physical causal convolution once over unique segments. At a branch, complete 128-token parent chunks become a saved state; only the residual suffix is replayed with each child.

On B300, the exact 52-layer 128K CP2/EP2 model measured a 3.455131-second median rank-max step and 10.129934% useful MFU across five steady samples with 1.36% CV. No post-warm compilation, code generation, or autotuning was observed. A reduced 39-layer workflow measured 43,624 physical tok/s in the isolated trainer, 43,469 with matched live inputs, and 41,273 end to end. The matched-core result is within 0.36% of isolation, which is the evidence that the rewritten Mamba path survives the real training pipeline.

The planner predicts time, not token count

Equal tokens do not imply equal work. A full ancestor rectangle, a causal local block, an indexer candidate range, a local GDN fork, and a chained GDN shard have different throughput and communication. ART's planners model achieved kernel throughput, bytes moved, measured bandwidth, launch latency, summary-scan time, and model dimensions, then minimize the predicted maximum exposed rank time.

Build a work matrix before assigning owners

For attention, the planner first computes an exact matrix whose entry W[i,j] is the number of visible query-key pairs between query chunk i and key chunk j. This captures causal triangles, full ancestor visibility, ragged branches, and empty intersections in one object. Token count alone cannot distinguish two assignments with the same query rows but very different visible KVs. 

T_stage = launch
        + visible_pairs / achieved_pair_throughput
        + query_rows / merge_throughput
        + range_count * range_latency
        + remote_underfill_penalty

T_exchange = collective_latency + bytes / achieved_bandwidth

T_forward(rank) = simulate(local compute || ordered KV fetch waves)
T_backward(rank) = max(stage compute path, asynchronous dKV completions)
objective        = max_rank(T_forward + T_backward)

The forward simulator starts all remote exchanges, places local attention on the compute path, and starts each remote stage at the later of compute availability or its fetch-ready time. Backward walks stages in reverse and tracks each asynchronous dKV reduction to completion. This is why the model can prefer a plan with more total network time but less exposed network time. Coefficients come from achieved kernel throughput, bandwidth, and launch/range measurements, not theoretical FLOP counts alone.

Search a bounded neighborhood, not every token partition

With C chunks and N ranks there are N^C raw ownership vectors. ART never enumerates them. It starts from a contiguous assignment weighted by query work, tries a bounded number of remote-wave counts, identifies the predicted slowest rank, and evaluates moving only its highest-value candidate chunks. An accepted move must lower predicted critical-path time. Search stops when no candidate improves the objective or the step budget is exhausted; larger chunk sets tighten that budget. Contiguous and folded layouts remain candidate seeds, not separate execution paths. 

best = None
for waves in bounded_wave_counts:
    owners = contiguous_seed(query_work)
    for _ in bounded_steps:
        slow = argmax(simulate(owners, waves).rank_time)
        move = best_improving_move(
            chunks=highest_value_chunks_owned_by(slow),
            destinations=other_ranks,
        )
        if move is None:
            break
        owners = move.owners
    best = min_by_predicted_max_rank_time(best, owners)

The chunks stay contiguous in physical token order so one ownership vector materializes into a small number of range intersections. The rank's set of chunks does not need to be contiguous. This is the compromise that makes the search fast enough for per-input planning while retaining arbitrary tree shapes.

One planner, architecture-aware facts

Generic dense attention uses the wall-time simulator above. GLM adds a model-derived work profile for every physical pipeline stage: projection and sparse-attention FLOPs per query token, indexer tile pairs, KV HBM traffic, fetch/reduce bytes, checkpoint/top-k memory, remote peer count, and ownership-range count. Those layouts are compared by their physical resource maxima and fragmentation; this is not falsely collapsed into one universal millisecond coefficient. GDN has its own wall-time model because its choice is local fork versus chained recurrence. It predicts local and chain throughput, layout all-to-all, summary bytes, prefix/suffix scans, parent-state exchange, and model dimensions fitted across 9B, 35B, and 397B shapes.

This matters most at decision boundaries. A planner tuned to make one benchmark choose "mixed" instead of "all local" will fail as soon as a completion grows by a few tokens. A runtime model should predict both plans' actual time and switch where the curves meet. Otherwise adding one token can flip from a good local plan to a catastrophically slower chain plan. The runtime model is evaluated on held-out shapes and workloads, not selected to force one benchmark's desired ownership class.

From one operation to two nodes

The following results answer different questions and should not be collapsed into one speedup. Operation labs isolate CP algorithms with production tensor shapes. Reduced full-model runs include surrounding layers and memory. Multinode runs include the real 24-layer GLM model, expert parallelism, and transport. All weak-scaling rows add physical tree tokens as ranks are added.

Dense attention stays nearly flat

On H200 with Qwen3.5-35B attention shapes, the accepted fixed tree measured 19.54/19.98/20.47 ms at CP2/4/8 while global tokens grew from 81,920 to 327,680. Varied completion lengths measured 19.72/20.47/20.85 ms. Fresh latest-source CP2/CP4 reproduction measured 19.405/19.853 ms fixed and 19.530/20.498 ms varied. That is the behavior weak scaling is supposed to produce: 4x the work from CP2 to CP8 for about 5% to 6% more layer time.

The chart normalizes each series to CP1 and draws ideal weak scaling at 1.0x. The visible jump is CP1 to CP2, not continued degradation with every rank. CP1 has one local attention call and no transport or stage merge. CP2 activates a remote KV exchange, another attention stage, FP32 softmax merge, and inverse dKV reduction. Those fixed distributed costs add about 2.2 ms on the short workload. From CP2 to CP8, local visible-pair work remains roughly fixed and most additional exchange stays under attention, so four times the global work adds only 0.9 to 1.1 ms.

A benchmark issue worth fixing

A fresh B300 CP2 smoke measured 58.94 ms, about 3x the H200 result. This is not a CP scaling failure: production currently forces FlexAttention's Triton backend on Blackwell compute capabilities 10/11, while H200 selects Flash. The backward backend dominates the gap. Blackwell dense CP needs a separate backend qualification before its numbers should appear beside H200.

Changing-input cold roles

In the first latest-source CP2 varied run, four disjoint warmup trees did not assign a partial-query merge to rank 0. Measured sequence 105 was its first such role, so _stage_merge_backward_row_kernel compiled inside backward and the peer waited at dKV reduction. This was a one-time role compile, not 600 ms of NCCL and not token-count specialization. The rerun used sixteen disjoint warmup trees. Sequence 105 then measured 20.260 ms and the sixteen-sequence median was 19.536 ms, with no measured compile cliff. Token counts remain runtime arguments; the remaining cold key is a finite rank-role signature that deployment warmup must cover.

Why not pipeline parallelism?

At fixed work, CP-only GLM reached 14,011 tok/s on eight GPUs and 27,964 on sixteen. PP2 reached 11,024 and 21,610; PP4 reached 20,134 on sixteen. PP transport itself was small. Pipeline bubbles, heterogeneous stage time, and source ownership left GPUs idle. Virtual pipeline stages helped, as expected, but did not close the gap for these matched rows. This is evidence against the tested PP alternatives, not a theorem that CP beats every possible model parallel layout.

What did not become free

  • Rollout supply. CP cannot train trajectories that generation did not produce.
  • Unshared data. Unrelated sequences gain capacity from CP, not prefix reuse.
  • Planner cadence. Tree parsing, search, and block metadata remain real per-input work even when lookahead hides them.
  • Recurrent summaries. All-chain trees expose more scan and state communication than local forks.
  • Sparse backward. GLM sparse MLA backward is still the dominant operation bucket.
  • Cold roles. Dynamic extents prevent token-shape recompiles, but every static kernel role must still be warmed.
  • Hardware backends. The B300 Triton/Flash gap needs its own optimization and validation.
  • Mamba scaling evidence. The exact CP2 and live-pipeline results are qualified; a CP1/2/4/8 weak-scaling matrix has not been measured and is not extrapolated here.

The original goal was to fit a longer tree. The more useful result is that a longer tree often makes the machine more productive. Shared prefixes stop consuming the row repeatedly; context parallelism lets the remaining unique work grow with the machine; architecture-specific algebra keeps that growth from turning into serial communication. Dense attention merges softmax statistics. GLM merges routes before sparse attention. GDN composes affine state summaries. Mamba moves the partition to heads.

That is the common design: preserve the tree, choose the algebra the layer actually supports, and measure the entire path that real variable-length training will execute.
